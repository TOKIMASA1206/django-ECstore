# Quiet Journey - ブログ機能付きECサイト

## 概要

本プロジェクトは、ブログ機能を搭載したECサイトです。
IT留学終了後、長期インターンの獲得を目指す中で、自身の技術力を可視化できる成果物の必要性を強く感じ、Djangoを用いたECサイトを個人で開発しました。
単なる商品販売にとどまらず、「ストーリーを伝える仕組み」としてブログ機能を組み込み、ユーザーの購買体験をより豊かにすることを目指しました。


## 背景

普段グッズを買わない友人や自分が、好きなアーティストのグッズだけは思わず購入してしまう。
このような体験から、「なぜ買いたくなるのか？」を深掘りした結果、制作の裏側や作り手の想いが共有されることで生まれる「BTS（Behind-the-Scenes）効果」に気づきました。

このBTS効果により、ユーザーに共感や親近感が生まれ、購買意欲が高まるのではないかという仮説を立て、ストーリー性のあるECサイトとして、ブログ機能の実装に取り組みました。

### チーム

個人開発です。要件定義、画面設計、API設計、DB設計、認証、CRUD、決済連携、デプロイまで全工程を自ら担当しました。
GitHub、Notionによる仕様整理など、実務を意識した開発プロセスを意識しています。

## 解決手法

これまでにインプットしてきたWeb開発の技術を一通りアウトプットすることを意識し、フルスタックに幅広く取り組みました。

- [リポジトリ（GitHub）](https://github.com/TOKIMASA1206/django-ECstore/tree/dev)  
- [デプロイ済みサイト（Render）](https://qj-ecsite-dev.onrender.com/)

#### 最終的にできたもの

- 使用技術：
  - バックエンド：Django（Python）
  - フロントエンド：HTML / CSS / JavaScript
  - 決済連携：Stripe API
  - 画像管理：Cloudinary
  - リッチエディタ：django-ckeditor
  - デプロイ：Render

- 主な動線：
  1. トップページから商品一覧へ遷移し、商品を閲覧・カートに追加
  2. プロフィールを登録後、Stripe決済で購入
  3. 管理者ユーザーはブログ投稿が可能。

- フレームワークの選定の意図：
  - Laravelで習得したMVCフレームワークの知見をDjangoに応用
  - 大学研究でPythonを使うため、業務レベルでのPython経験を積むことを目的に選定
  - 1つのWebアプリケーションで、フルスタック開発工程をすべて一人で完結させる経験を重視




## 技術的な深掘り

### ポイント1: お気に入り機能の非同期通信による操作感向上

#### 課題

お気に入り操作時にページ遷移が発生し、操作感が悪化したため、その改善を行った

#### 対応

- DjangoのViewに対して、JavaScriptのfetch APIを使用して非同期POST処理を実装
- レスポンスを受け取った後、フロントエンド側でボタンの表示を即座に切り替えることで、ページ遷移なしでスムーズにお気に入り登録・解除を可能に

---

### ポイント2: Stripeを用いたセキュアな決済処理

#### 課題

個人開発においても安全性・信頼性の高い決済手段が必要

#### 対応

- 信頼性の高いStripe APIを導入
- 顧客情報やカート情報からCheckout Sessionを生成し、Stripeのホストページへ遷移させて決済を完了
- 成功時・キャンセル時のリダイレクトURLを設定することで、注文の状態を追跡・管理可能に

---

### ポイント3: ブログ機能によるBTS体験の提供

#### 課題

「ストーリーのある商品」ほど売れやすいという仮説に基づき、制作背景やスタッフの日常を伝える手段が必要

#### 対応

- django-ckeditorを用いて、画像挿入・見出し・リンクなどが可能なリッチエディタを導入
- 記事投稿によって、アーティストやクリエイターが制作背景を発信可能に


## 成果

開発した成果物は**ポートフォリオとして整理し、インターン選考での実績資料として提出**しました。  
その結果、**実際にDjangoを使用する長期インターンに合格**し、実務に近い形での開発経験につながっています。


## 今後の展望

- ブログと商品情報の紐付け機能(**最優先**)

記事から該当商品のページへリンクし、背景→購入へつながるUXを実現したいです。

- コードのリファクタリング

当時は設計力やコーディングの知見が十分ではなかったため、冗長なロジックや不適切なファイル構成が一部存在しています。
今後も学習を続け、より見通しの良い設計や保守性の高い構造へと改善していきたいです。

- 購入完了時の自動メール送信機能

SendGridなどのメールAPIを用いた実装したいです。

- コメント・レビュー機能の導入

購入者の声が可視化されることで、信頼性や共感をさらに高めたいです。
